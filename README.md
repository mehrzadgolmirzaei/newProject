# آکادمی پاتولوژی ویورا

سامانه‌ی آموزش تخصصی پاتولوژی بر پایه‌ی موارد دشوار، برای آزمایشگاه پاتوبیولوژی ویورا.
پاتولوژیست‌های تأییدشده موارد خود را ثبت می‌کنند؛ همکاران تشخیص خود را می‌نویسند، پاسخ و آمار را می‌بینند و بحث می‌کنند.

**فناوری:** Next.js 16 (React 19، TypeScript) · PostgreSQL + Prisma · OpenSeadragon (زوم عمیق) · sharp/libvips (پردازش تصویر)

---

## قابلیت‌های فاز یک

| بخش | توضیح |
|---|---|
| **مورد ناشناس** | تشخیص، افتراقی‌ها، بحث و نشانه‌های «لودهنده» تا پیش از پاسخ کاربر **اصلاً به مرورگر فرستاده نمی‌شوند** (نه فقط پنهان). جست‌وجو هم روی تشخیص موارد ناشناس کار نمی‌کند. |
| **پاسخ و آمار** | تطبیق خودکار پاسخ با تشخیص نهایی و معادل‌ها (مخفف‌ها، ترتیب واژه‌ها، املای بریتانیایی) + تصحیح دستی توسط ارائه‌دهنده. توزیع پاسخ همکاران و درصد درستی. |
| **نمایشگر اسلاید** | زوم عمیق (Deep Zoom) مثل میکروسکوپ، نقشه‌ی کوچک، چرخش، تمام‌صفحه، نوار تصاویر، نشانه‌گذاری (پیکان/بیضی/کادر با برچسب). |
| **اسلاید دیجیتال کامل** | فایل‌های SVS/NDPI/MRXS… با vips + OpenSlide به کاشی تبدیل می‌شوند (در ایمیج Docker فعال است). |
| **ساختار استاندارد مورد** | شرح حال، تصویربرداری، ماکروسکوپی، میکروسکوپی، **جدول IHC ساختاریافته**، مولکولی، افتراقی‌ها، بحث، نکات کلیدی، منابع. |
| **بحث** | رشته‌ای (پاسخ به نظر)، ویرایش/حذف، سنجاق «نکته‌ی آموزشی»، پنهان‌کردن توسط ارائه‌دهنده یا مدیر. |
| **ورود** | با نام کاربری و رمز عبور (`AUTH_METHOD="password"`، پیش‌فرض) یا با کد پیامکی (`AUTH_METHOD="otp"`، کاوه‌نگار یا sms.ir) + تکمیل پروفایل با شماره‌ی نظام پزشکی + تأیید مدیر. مدیر می‌تواند مستقیماً حساب بسازد و رمز جدید تعیین کند. |
| **نقش‌ها** | مدیر / ارائه‌دهنده / عضو · «ارائه‌دهنده‌ی مورد اعتماد» بدون صف بازبینی منتشر می‌کند. |
| **استودیو** | ویرایشگر بخش‌بندی‌شده با ذخیره‌ی خودکار، آپلود با نوار پیشرفت، فهرست بازبینی حریم خصوصی، پیش‌نمایش. |
| **مدیریت** | تأیید کاربران، صف بازبینی (انتشار / بازگرداندن با یادداشت)، «مورد هفته»، بایگانی، گزارش همه‌ی رویدادها. |
| **حریم خصوصی** | حذف EXIF/متادیتا، حذف فایل خام پس از پردازش، عدم ذخیره‌ی نام فایل، عدم استخراج برچسب لام از WSI، سن ۹۰+. |
| **امنیت** | نشست در دیتابیس (قابل ابطال)، رمز عبور با scrypt، محدودیت نرخ ورود/ثبت‌نام/پیامک/نظر، CSP و هدرهای امنیتی، بررسی Origin در آپلود، اعتبارسنجی تنظیمات در شروع. |
| **فارسی** | راست‌به‌چپ کامل، ارقام و تاریخ شمسی، یکسان‌سازی «ي/ك» عربی در ذخیره و جست‌وجو، فونت وزیرمتن روی سرور خودتان (بدون CDN خارجی). |

## اجرای محلی (توسعه)

پیش‌نیاز: **Node.js 20.9+** و **PostgreSQL 14+** (یا Docker).

```bash
# ۱) دیتابیس — اگر Postgres ندارید:
docker run -d --name viora-db -e POSTGRES_USER=viora -e POSTGRES_PASSWORD=viora -e POSTGRES_DB=viora -p 5432:5432 postgres:16-alpine

# ۲) نصب و تنظیمات
npm install
cp .env.example .env

# ۳) ساخت جدول‌ها و داده‌ی نمایشی
npm run db:deploy                     # اعمال migration های موجود در prisma/migrations
npm run db:seed

# ۴) اجرا
npm run dev                           # http://localhost:3000
```

**ساخت حساب مدیر** (یا ارتقای حساب موجود به مدیر و تعیین رمز جدید):
```bash
npm run admin:create -- --username mehrzad --password "رمز-دلخواه" --name "نام شما"
```

**حساب‌های نمایشی** (رمز عبور همه: `viora1234`):

| نام کاربری | نقش |
|---|---|
| `admin` | مدیر |
| `dr.kazemi` | ارائه‌دهنده (انتشار مستقیم) |
| `dr.razavi` | ارائه‌دهنده (با بازبینی) |
| `dr.ahmadi` · `dr.mousavi` | عضو تأییدشده |
| `dr.sadeghi` | عضو در انتظار تأیید |

> در حالت `AUTH_METHOD="otp"` ورود با شماره‌ی موبایل است (حساب‌های نمایشی: `09120000000` تا `09125555555`) و با `SMS_DRIVER="console"` کد روی صفحه‌ی ورود نمایش داده می‌شود.

## راه‌اندازی روی سرور

### گزینه‌ی ۱ — لیارا (پیشنهادی برای مخاطب داخل ایران)

1. در لیارا یک **دیتابیس PostgreSQL** و یک **برنامه‌ی Docker** بسازید؛ برای برنامه یک **دیسک** با نام `media` بسازید.
2. متغیرهای محیطی برنامه را از روی `.env.example` تنظیم کنید:
   - `DATABASE_URL` ← آدرس اتصال دیتابیس لیارا
   - `SITE_URL` ← دامنه‌ی نهایی، مثلاً `https://atlas.viora-lab.ir`
   - `AUTH_SECRET` ← خروجی `openssl rand -base64 48`
   - `AUTH_METHOD` ← `password` (پیش‌فرض) یا `otp`
   - فقط برای `otp`: `SMS_DRIVER`، `SMS_API_KEY`، `SMS_TEMPLATE` ← از پنل کاوه‌نگار یا sms.ir (الگوی «کد تأیید» با یک متغیر)
3. `liara deploy` — فایل `liara.json` آماده است. migration ها هنگام شروع خودکار اعمال می‌شوند.
4. ساخت حساب مدیر (یک بار، از کنسول برنامه در پنل لیارا):
   ```bash
   node scripts/create-admin.mjs --username admin --password "یک-رمز-قوی" --name "نام شما"
   ```

> **فضای ذخیره‌سازی ابری (اختیاری):** اگر حجم تصاویر زیاد شد، به‌جای دیسک از فضای ابری S3 لیارا یا آروان استفاده کنید: `STORAGE_DRIVER="s3"` و متغیرهای `S3_*` و `MEDIA_PUBLIC_URL`. روی باکت، دسترسی عمومی خواندن و CORS برای دامنه‌ی سایت (متد GET) را فعال کنید.

### گزینه‌ی ۲ — سرور مجازی (VPS) با Docker

```bash
cp .env.example .env        # مقادیر production را پر کنید
docker compose up -d --build
docker compose exec web node scripts/create-admin.mjs --username admin --password "یک-رمز-قوی" --name "نام شما"
```
جلوی آن یک Nginx/Caddy با HTTPS بگذارید. برای دسترسی سریع‌تر از داخل و خارج ایران می‌توانید CDN ابرآروان را جلوی دامنه قرار دهید.

### پیش از راه‌اندازی واقعی
```bash
npm run demo:clear -- --users    # حذف موارد و حساب‌های نمایشی
```

## کارهای روزمره

| کار | دستور |
|---|---|
| تغییر ساختار دیتابیس | `prisma/schema.prisma` را ویرایش و `npm run db:migrate -- --name توضیح` |
| مشاهده‌ی دیتابیس | `npm run db:studio` |
| پردازش دوباره‌ی تصاویر ناتمام | `npm run media:reprocess` |
| آزمون‌ها | `npm test` |
| بررسی نوع‌ها | `npm run typecheck` |

**نام سایت، شعار و نام آزمایشگاه:** فقط `src/lib/site.ts`.
**زیرتخصص‌ها، رنگ‌آمیزی‌ها و برچسب‌ها:** `src/lib/taxonomy.ts`.
**رنگ‌ها و ظاهر:** متغیرهای ابتدای `src/app/globals.css` (حالت تیره خودکار).

## ساختار پروژه

```
prisma/
  schema.prisma         مدل داده (تنها مرجع)
  seed.ts               داده‌ی نمایشی
src/
  app/                  صفحه‌ها (App Router)
    cases/              کتابخانه‌ی موارد و صفحه‌ی هر مورد
    studio/             استودیوی ارائه‌دهنده (ویرایشگر مورد)
    admin/              مدیریت: کاربران، بازبینی، موارد، رویدادها
    account/            پیشرفت و نشان‌شده‌های کاربر
    login, onboarding   ورود (رمز عبور یا پیامک)، ثبت‌نام و تکمیل پروفایل
    api/uploads         آپلود جریانی فایل‌های حجیم
    media/              سرو فایل‌ها در حالت ذخیره‌سازی محلی
  actions/              عملیات سمت سرور (Server Actions)
  components/
    viewer/             نمایشگر اسلاید و لایه‌ی نشانه‌گذاری
    studio/             ویرایشگر مورد، مدیریت تصاویر، ویرایشگر نشانه
    case/ admin/        اجزای صفحه‌ی مورد و مدیریت
  lib/
    auth.ts             نشست‌ها و قوانین دسترسی (همه‌ی تصمیم‌ها یک‌جا)
    cases.ts            کوئری‌ها — و قانون «پاسخ پیش از ثبت به مرورگر نمی‌رود»
    media.ts            پردازش تصویر و WSI
    matching.ts         تطبیق پاسخ با تشخیص (+ آزمون)
    storage.ts          درایور ذخیره‌سازی محلی / S3
```

## نقشه‌ی فازهای بعد (پیشنهادی)

- اعلان پیامکی/ایمیلی «مورد هفته» و پاسخ به نظرها
- مجموعه‌های موضوعی (مثلاً «۱۰ مورد دشوار بافت نرم») و آزمون زمان‌دار برای دستیاران
- امتیاز بازآموزی و گواهی مشارکت
- نسخه‌ی انگلیسی برای مخاطب منطقه‌ای
- اتصال به سامانه‌ی اطلاعات آزمایشگاه (LIS) برای فازهای عملیاتی
